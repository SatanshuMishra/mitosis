# Decisions for TOML

Questions the document left open, settled. These are binding.

- Newlines inside multi-line strings are preserved exactly as written. LF
  stays LF and CRLF stays CRLF; no platform normalization is performed.

- A lowercase `t` between date and time and a lowercase `z` offset are
  accepted.

- Supported fractional-second precision is microseconds. A seventh and later
  fractional digit is dropped, never rounded.

- A seconds value of 60 is rejected.

- Offset date-times become aware `datetime.datetime`, local date-times naive
  `datetime.datetime`, local dates `datetime.date`, and local times naive
  `datetime.time`.

- A dotted key may descend into a table a header created implicitly as a
  super-table. That table then counts as dotted-key-defined, so a later
  header naming it is rejected while a header naming a deeper table is still
  allowed.

- Comments and newlines are permitted anywhere inside inline-table braces
  that whitespace is, matching arrays.

- The deliverable is a parser only: `loads` and `load`. No serializer is
  built, because the document specifies syntax and its mapping to a hash
  table and states no emission rules.

- `load` takes a binary file object and decodes it itself, so the whole-file
  UTF-8 check runs on every file read.

- Every error raised for invalid input is the package's own decode error.
  No other exception type, including `ValueError` from a standard-library
  conversion, may escape either entry point.
