# Decisions for RFC 6902

Questions the document left open, settled. These are binding.

- The error hierarchy has one root class with exactly two branches: a
  normative requirement violated by the patch document, and an operation that
  ran but did not succeed. Nothing else subclasses the root directly.

- RFC 6901 is the document's one normative dependency. The pointer grammar,
  the unescaping order and the array index rules are taken from it.

- A token that is not valid for the value it is applied to is a missing
  target, not a syntax error, because the same pointer string is valid
  against another document.

- Duplicate member detection happens only in the text-level parser. After
  JSON parsing into Python data a duplicate cannot be observed, so the
  operation-object layer checks presence and type only.

- The MUST-contain clauses for `value` and `from` are enforced at parse time,
  so each operation module receives a record already carrying the members it
  defines.

- An add whose parent exists but is a string, number or literal is treated
  like the missing-parent case.

- An array index greater than the array length is a missing target.

- Removing the root is an operation failure.

- Replace is an existence check followed by add, so the root may be replaced.
  It is identical to remove-then-add everywhere else.

- Violating the proper-prefix rule of move is an invalid patch, not an
  operation failure, because it is a property of the operation object alone.

- A copied container is shared by reference, which is safe because no
  operation mutates in place.

- A test whose target does not exist is a missing target, not a failed
  comparison. Both are operation failures and either terminates the patch.

- The text-level parser rejects a duplicate member name anywhere in the patch
  text.

- Evaluation always terminates at the first error, and the untouched original
  is the atomic outcome.

- Operations are parsed as they are reached rather than all validated up
  front, which is unobservable in the result.

- `jsonpatch` and `jsonpatch.operations` are implicit namespace packages until
  the public-surface Step lands; only that Step creates their `__init__.py`.
