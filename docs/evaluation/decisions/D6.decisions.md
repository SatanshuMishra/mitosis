# Decisions for BitTorrent BEP 3

Questions the document left open, settled. These are binding.

- Bencoded strings decode to bytes and the encoder accepts only bytes for
  strings. UTF-8 decoding happens in the layers that know a value is text,
  because keys sort as raw strings and the piece hashes are binary.

- The decoder is strict and total. It rejects unsorted or duplicate keys,
  leading zeros, negative zero, non-string keys, and any bytes left after
  the top-level value, so a valid input re-encodes byte for byte.

- The encoder accepts int, bytes, list, and dict with bytes keys, and
  rejects bool, str, and every other type.

- The info hash is the SHA1 of the re-encoded info dictionary after strict
  decoding, which equals the SHA1 of the raw info substring.

- Piece length must be a positive integer but need not be a power of two.

- The number of twenty-byte hashes must equal the piece count implied by the
  total length and piece length. A mismatch is rejected.

- The announce URL, the name and every path component are decoded as UTF-8
  and invalid UTF-8 is rejected. Keys the document does not name are
  ignored.

- Lengths must be non-negative integers, the file list must be a non-empty
  list of dictionaries, and the multi-file total is the sum of the file
  lengths in list order.

- The layout functions take primitives (piece length, ordered file lengths,
  ordered hashes) rather than the metainfo object.

- The block size is 2^14 bytes. A piece splits into 2^14 blocks with a
  truncated tail.

- Port availability is a caller-supplied predicate. The selector never binds
  a socket.

- The peer id is twenty bytes from `os.urandom` with no client prefix
  convention.

- The empty event is never emitted; a regular announce omits the event key
  entirely.

- The event to send is a pure function of first announce, complete at start,
  now complete and stopping. Completed is never sent when the file was
  complete at start.

- The bytes-left count is supplied by the caller and never derived from
  downloaded bytes or the file length.

- An announce URL that already carries a query string is extended with an
  ampersand.

- A response carrying a failure reason yields a failure value holding the
  decoded message rather than raising.

- The peers value must be a list of dictionaries. The compact byte-string
  form is outside this document and is rejected as unsupported.

- Peer id is returned as raw bytes, the address as a string, and the
  interval and port as ints. Missing or wrongly typed required keys are
  rejected.

- Handshake decoding tolerates any value in the eight reserved bytes and
  returns them; encoding always emits zeros.

- The handshake is parsed in two stages, the 48-byte prefix through the info
  hash and then the peer id, so a serving side can match the hash before
  answering.

- A mismatched info hash, a mismatched expected peer id, a wrong length
  prefix and a wrong protocol string each produce a distinct rejection. The
  handshake layer performs no I/O.

- The frame reader is a pure function from carried-over buffer and new bytes
  to complete message bodies and remaining buffer. Zero-length frames are
  consumed and not emitted, but the result reports that traffic arrived.

- The keepalive interval is a constant of 120 seconds.

- A bitfield is decoded against a known piece count. A length that does not
  match, or a nonzero spare bit, is rejected as malformed.

- A request or cancel whose length exceeds 2^14 is rejected with a distinct
  error. Lengths up to and including 2^14 are accepted.

- Messages are immutable typed values with a single encode and decode over
  the frame body, excluding the length prefix.

- Receiving choke clears our outstanding requests and sending choke clears
  the peer's queued requests.

- Interest is the peer having at least one piece we lack, recomputed
  whenever either side's pieces change. The interested or not-interested
  message is emitted only when the flag changes.

- A bitfield received after any other message is a protocol error. A piece
  received that matches no outstanding request is accepted and marked
  unexpected rather than rejected.

- The pipelining depth defaults to five outstanding requests per peer and is
  a parameter.

- Random piece order is drawn from a caller-supplied random source.

- Endgame begins once every piece we lack has at least one outstanding
  request. From then every remaining block is requested from every unchoked
  peer that has it, and each arriving block yields cancels to the others.

- Download and upload rates are supplied by the caller per peer. The choker
  measures nothing and is a pure function of the peer table, the clock and
  its own previous decision.

- An uninterested peer is unchoked when its rate beats the fourth-best
  interested peer. When it becomes interested, the interested unchoked peer
  with the worst rate is choked.

- A connection is new until it has been optimistically unchoked once, and
  carries weight three against one in the rotation draw, which uses a
  caller-supplied random source.

- The ten-second recompute and thirty-second rotation are measured from
  timestamps passed in by the caller, never from the wall clock.

- The session is a pure state machine. Events in are bytes from a peer, a
  tracker response, a verified local piece, a clock tick and stop; actions
  out are bytes to a peer, an announce URL, a write of a block to a file
  span, and a connection to sever. It performs no I/O.

- One session serves one metainfo. Serving several downloads over one port
  is handled by the handshake helper.

- Resume is modelled by starting the session with a set of already verified
  pieces supplied by the caller, and the bytes-left count follows from the
  pieces not yet verified.

- After completion the session keeps serving requests until stop is called,
  which produces the stopped announce.
