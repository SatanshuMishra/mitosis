# Decisions for RFC 4180

Questions the document left open, settled. These are binding.

- A bare LF terminates a record. A bare CR outside a quoted field is a parse
  error.

- A double quote inside a non-escaped field is a parse error.

- Characters at or above U+0080 are accepted wherever TEXTDATA is accepted.
  Characters below U+0020 and U+007F are a parse error, except CR and LF
  inside a quoted field and the line-break characters between records.

- Empty input yields zero records. A final line break yields no extra record.
  Input ending in two consecutive line breaks yields a final record of one
  empty field.

- `parse` accepts only `str`. Bytes are decoded first through the media-type
  layer.

- `parse` does not enforce a uniform field count across records. That
  enforcement lives in the table layer.

- An unterminated quoted field is a parse error, as is any character between
  a closing double quote and the next comma, line break or end of input.

- A field is enclosed in double quotes only when it contains a comma, a
  double quote, CR or LF. Minimal quoting is the rule.

- Output ends with a trailing CRLF.

- Records of differing width raise a serialize error, as does a record with
  zero fields.

- A field containing a character below U+0020 or U+007F other than CR or LF
  raises a serialize error. Characters at or above U+0080 are written as-is
  without quoting.

- Type, subtype and parameter names are matched case-insensitively and the
  header value is emitted lowercase. The charset value is kept as given.

- The charset is validated with `codecs.lookup` at construction. A charset
  Python cannot look up is a media-type error.

- An omitted header parameter is modelled as `None`, meaning the caller must
  decide.

- A parameter value may be wrapped in one pair of double quotes; parsing
  strips that pair and performs no further unescaping.

- A type other than text/csv, a parameter name other than charset or header,
  a header value other than present or absent, and a repeated parameter each
  raise a media-type error.

- The table reader takes the header disposition as a required argument with
  no default. Passing `None` is a misuse and is not accepted.

- The table reader enforces uniform width across rows, and with a header
  present, that the header has the same number of fields as every row. The
  low-level parser stays liberal; strictness lives in the table layer.

- Reading empty input with a header declared present is a table error.
  With the header declared absent it yields a table with no names and no
  rows.

- Writing a table with names emits the header line as the first record. All
  line formatting is delegated to the serializer so the header line has the
  same format as a record line.
