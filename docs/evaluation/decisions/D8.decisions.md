# Decisions for gitignore pattern semantics

Questions the document left open, settled. These are binding.

- A trailing carriage return is removed before any other processing of a
  line.

- Only the space character counts as a trailing space. Tabs and other
  whitespace stay part of the pattern.

- Leading whitespace is part of the pattern. Only a `#` in the very first
  column makes a comment.

- A line whose body is empty once the negation prefix, trailing slash and
  trailing spaces are removed yields no pattern.

- Bracket expressions follow fnmatch(3): ranges, negation by a leading `!` or
  `^`, backslash escapes inside the brackets, and the POSIX named classes.

- A bracket expression never matches `/`.

- An unterminated `[` is a literal `[` character.

- A trailing `/**` matches only paths strictly inside the directory.

- An unanchored pattern is matched against the final path component only. A
  pattern naming a directory reaches that directory's contents through the
  matcher's ancestor walk.

- Whether a path is a directory is supplied by the caller. The matching layer
  never touches the filesystem.

- A source based at a directory applies only to paths strictly beneath it.
  That directory itself is never decided by the ignore file inside it.

- The top-level source has an empty base and applies to every path.

- Command-line patterns are treated as specified at the top of the working
  tree.

- An ancestor directory whose deciding rule is a negation is not excluded,
  and the walk continues to the next component.

- A directory's ignore-file source is requested only when the walk reaches
  that directory, so sources inside an excluded directory are never
  consulted.

- An ignore file that is a symbolic link is treated as absent. Nothing is
  read through the link and no error is raised.

- Files are read as bytes and decoded as UTF-8 with surrogateescape.

- The top-level directory is given by the caller. No upward search for a
  `.git` directory is performed.

- The value of the excludes-file setting is supplied by the caller; the
  library does not parse the git config file. A supplied value with a
  leading `~` is expanded.

- The common git directory is taken from the environment when set and
  non-empty, otherwise the `.git` directory under the top level. A relative
  value is joined onto the top-level directory.

- When neither the XDG config directory nor the home directory is set, no
  excludes-file default exists and that source is absent.

- Files at the standard locations are read following symbolic links. The
  symlink rule covers only ignore files in the working tree.

- In the convenience entry point a symbolic link is never a directory, and a
  path that does not exist is a non-directory.

- Command-line patterns are strings parsed with the same line rules as file
  contents and form a single source anchored at the top.

- There is no separate extra-files option. Callers read such files through
  the location reader and build a matcher directly.

- The `foo/*` example is verified at the rule level, because through the full
  decision a file below it is still ignored by way of its excluded parent.

- The status transcript is reproduced as a set of ignored and not-ignored
  verdicts over the listed untracked paths, not as text output.
