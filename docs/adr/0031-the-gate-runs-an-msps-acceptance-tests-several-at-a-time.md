# The gate runs an MSP's acceptance tests several at a time

Status: accepted. Amends 0011, 0028 and 0029.

The gate ran an MSP's acceptance tests one at a time in one clean checkout. Each test starts its own process and reads only its own checkout, so nothing but the order kept them apart, and the order is where a gate's time went: the 59 past runs whose gate logs are on disk spent 33,940 seconds in 1,539 acceptance runs against the finished work, 5,130 of them in one run's 41 tests and 10,405 in another's 47.

The gate now runs up to as many of an MSP's tests at once as the build may run at once, the `--concurrency` number, each in a clean checkout of its own for the length of its run, reset before it as 0028 says. The first test runs alone. A node_modules folder it installs, which 0029 keeps, is then copied into every other checkout as a copy-on-write clone, and on a filesystem without one each checkout installs for itself. A test that does not pass beside others is run again alone before it is judged, in one more checkout the gate makes only then, after every run beside others has ended, so nothing another test wrote can reach the run that decides it; that checkout installs for itself. The run alone decides only when it ends with 0 or 1. When nothing can judge it, the run beside others stands, so a failing test whose run cannot start without what the first test installed still holds its MSP, as it did one test at a time, and its failing output is then in the kept log. The log of a first run beside others stays beside the log of the second, as `<n>-with-work.beside.log`, until the MSP's next gate removes it. A gate with a `--gate-setup` command keeps one checkout, as before, because no measured repository uses one, and so does a gate of two tests or a build under a `--concurrency` of one, where nothing would run at once. MSPs still finish one after another, so a test run again alone is alone in the build. Under `--worker-sandbox` every checkout has its own profile, temp folder and mark; those of every checkout after the first sit under one folder beside the gate's log folder, which the gate removes when it ends, whatever an earlier, wider gate left there. When one run raises an error, the gate starts no test still queued and reports the error once the runs in flight end.

The sandbox profile of 0011 now also refuses a signal to any process outside the sender's own sandbox, for Workers, gate runs and lock-stage checks alike. Before, a sandboxed process could end any process of the caller's account: another run's, mitosis's own, or, once tests run at once, the test beside it, and a test ended by a signal exits with neither 0 nor 1, so nothing judges it. A sandboxed process still ends its own children, and mitosis, outside every sandbox, still ends each run's processes.

Under 0018 this was measured by replaying the gates of the eight built benchmark changes from one copy of the code, one test at a time and then four. The seven changes other than A take 261.8 seconds and then 103.0, and A takes 173.2 and then 152.4, with every verdict equal, no referee write and no test run again alone. The form judged before it ran a test again in the first checkout, which later tests had also written in, so a later test could turn an earlier failing test into a pass. A form that kept one more checkout from the start for the runs alone closed that and took 163.4 seconds on A with four against 166.1 with one, the fifth copy of A's dependency folder costing what running at once saved, so that checkout is made only when a test needs it. The first form built, in which every checkout installed for itself, was slower on A, 188.9 seconds against 171.9, because copying A's 89,020-entry dependency folder takes 10.4 seconds a checkout where a clone of it takes 0.95, so it was not adopted. A's gain stays small because the reset before each test reads and hashes each of its 9,444 files, 0.75 seconds alone and about 5 with four at once.

The cost is that two tests can now meet through anything outside their checkouts: a port, a database, a file under the home folder. The run again alone keeps such a test from failing for that reason, at the price of running it twice, and the only record that it happened is the kept log, because the result format has no field for it. A test that fails against the work for a real reason pays that price too, so a gate of failing tests is slower several at a time than one at a time: a stub build of five failing tests that each wait a second ends in 7.3 seconds with four at once and in 6.2 with one. What the first test writes into the kept folder reaches every checkout the others run in, where it reached every later run before; what a later test writes there reaches only later runs in its own checkout, and a test run again alone sees only what it and earlier runs alone install, so a test that passed only on what another test left there is now held. A gate holds one checkout per test in flight, and one more once a test is run again alone, so it uses that much more disk. A keyboard interrupt during a gate is seen when the runs in flight end, as it is while Lanes run.

Finishing MSPs that do not wait on one another at once was measured with this and is not adopted. It built benchmark change A in 702 seconds where the same code finishing one MSP at a time took 900, both merging 70 of 111 tests, and its independent reviews then showed tests of two MSPs meeting through a port with no run that is alone in the build: a stub build that ships with one MSP finishing at a time was held, after a repair that could fix nothing, with two. It returns when every acceptance run of a build takes a turn that all its gates share and a run again alone holds that turn by itself.

This reopens when a build ships a test that passes alone and fails beside others for a reason that was a defect in the work, when a real run's gates spend more on second runs of failing tests than running at once saves them, when the resets of a real run take more than a tenth of its gate, which is what a cheaper reset would be measured against, or when a repository with a gate setup command spends gate time worth dividing.
