# Each MSP locks its own checks on its own branch

Status: accepted. Supersedes the lock commit on the feature branch and the single top-level lock record of ADR 0012.

mitosis runs one check-author per MSP, mapped by its msp label or, for an unlabelled check-author, by which MSP's Steps' acceptance entries name each locked file. Each check-author writes its slice in its own clone at the feature base, and the slice is locked only when every test exits 1 on the base plus the slice and exits 0 once the check-author's probe writes inside the MSP's probe files are overlaid. The slice alone is committed onto the feature base as that MSP's lock commit, the first commit of its branch; the feature branch is never moved and nothing is pushed at lock time, so each MSP's pull request carries its own checks. A failed or parked lock holds back only its MSP and the MSPs that merge it, and each MSP keeps its own lock record and referee. We chose this over one lock on the feature branch because that put every MSP's red checks in every MSP's tree: in the Pathfinder run desktop-reliability-ux, 110 of the foundations MSP's 116 new failures were other MSPs' unbuilt checks. We chose the probe judgement over trusting the check-author's own report because a check that crashes in its harness fails today too, and only a passing run against a probe shows a build inside the write-set can pass it.
