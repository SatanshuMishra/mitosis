# The gate runs each acceptance test once, against the finished work

Status: accepted. Supersedes 0007 and 0013, ends 0024's rule at the gate, and amends 0025 and 0027. Amended by 0031.

The gate ran three stages the reference planner has no counterpart for: a second run of each test with the implementation reverted, up to 12 runs of each passing test against altered copies of the work, and one return of a weak or inert test to its Lane. Under 0018 each was measured by replaying the gates of seven built benchmark changes with the stage on and off, and by reading every weak and inert verdict saved from past runs. Mutation gave two weak verdicts across those builds, both on one change, whose merged tests scored 600 of 613 before and after its Lane answered them; all 37 weak verdicts on record were read and none named a defect in a test, while mutant runs took 3 to 334 seconds of a gate and 5,070 of the 5,241 gate seconds of one past run. The return to the Lane fired once, cost 0.69 dollars and 933 seconds, and changed no score. The reverted run took 4 to 43 seconds of a gate and changed no verdict in the builds beyond setting five tests aside as guards. Alone, it raised 17 verdicts in past runs, across 10 Steps none of whose tests failed without the work: 12 on Steps that only add tests, 3 on a refactor that keeps behaviour and 2 on a Step whose cause could not be traced, none confirmed as a defect in a test. For a Step that only adds tests, or a refactor, the return asked the Lane for a test that fails without work that changes no behaviour.

The gate now runs each acceptance test once, against the finished work. A test that exits 0 passes; one that exits 1 gets its Lane one repair and then holds the MSP, as 0025 says; one the command cannot run is inconclusive. Nothing runs without the work, no copy of the work is altered, and no test returns to its Lane for passing. The result and state formats keep every field, because they are the program's to change: the weak and inert counts stay and read zero, each property's mutants field is null, and the list of reverted files is empty. A recorded gate that a resume reuses at an unchanged commit is judged again from its recorded exit codes, so a verdict an earlier version called weak or inert reads pass.

The cost is that the gate no longer shows that a test fails without the work. A skipped test, or one that asserts only that a function exists, passes, and the pull request's Testing table says a test passes against the finished work and nothing more. A plan with a lock stage still requires each locked test to fail at the feature base, as 0024 says. Whether a test has teeth is review's to judge, which 0025 already said of a test no mutant failed. This is reopened by the first build where review, or a failure after merge, shows a Step shipped with tests that pass without its work.
