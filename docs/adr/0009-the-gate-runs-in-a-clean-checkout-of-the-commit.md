# The gate runs in a clean checkout of the commit

Status: accepted

mitosis runs the gate, every mutant run and every acceptance run in a gate folder outside the Worker's worktree, written from the MSP commit's tree objects with replace objects, system and global config, attributes and filters kept out, and reset to its target tree before every run. Dependency folders come from the repository root, or from the `--gate-setup` command when one is given. A committed referee write, found by comparing tree objects the same way, is reverted and exits 9; files the commit does not carry are listed as ignored and never restored. We chose this over normalizing the Worker's worktree, because three review rounds found a new way to hide a file each time: ignore rules, virtual-environment markers, permissions, smudge filters and submodule-local config all let the Worker shape what mitosis saw. The cost is that the gate folder is not a git repository and holds raw blob bytes, reset before every run: a project whose tests run git prepares a top-level `.git` with `--gate-setup`, whose output survives the reset only at top-level names the commit lacks, and a referee-named one is a fatal referee write; a test that reads Git LFS content or needs checkout eol conversion ends inconclusive, because no setup can prepare a committed path.
