# Model replies come from structured output, with one re-ask of the same session

Status: accepted

mitosis reads a Worker's, decompose call's or brief call's reply only from the structured_output of the one JSON object the model command prints, checked against the reply's owned schema, and asks the same session once more through a caller-supplied --reask-command, with the schema errors, when the reply fails; a second failure fails that step. The caller's model templates therefore carry a {schema} placeholder, filled with a call schema derived from the owned schema, and {session_id}, which a template could previously leave out at the cost of unpriced calls. This amends 0003: a template without {session_id} is now refused rather than counted as missing, and a re-ask reuses the first call's session id rather than a fresh one, so its spend lands in that id's transcript; every first call still gets a fresh id. The call schema drops the 2020-12 $schema reference Claude Code refuses, and a schema whose root is a oneOf, which the API refuses at the top level, is passed wrapped as a reply property and unwrapped before the check. We rejected scanning output for the last JSON line, which took a stray object from a reply's prose as the reply, and a fresh-session retry, which asks a session that never did the work; we kept the model command a caller template rather than building claude's arguments in mitosis, which names no model command.
