# A test that passes without the work guards unchanged behaviour

Status: accepted.

A spec's acceptance tests often include rows for behaviour that must stay the same, such as a clean name still getting a branch, and those rows pass before the work exists, so the lock refused them and the gate called them inert; the denied-terms build lost all 7 of its Lanes to 17 of its 68 tests while the reference planner, which has no lock, built the same items. A test that passes without the work now counts as a guard when another test of its Step fails without the work, at the lock and at the gate. A guard must still pass with the work, is recorded as not-applicable so no contract changes, gets no mutants, stays out of the run history and is reported in the pull request as passing both ways, and a Step whose tests all pass without the work is still refused. We chose this over marking each guard in the spec, which would need a change to interphase, the items schema and the record across three repositories and would help no other author's spec, and over a new guard outcome, which would change the result and state contracts the pipeline vendors. The cost is that a guard proves only that the work left the behaviour alone, and a test that could never fail ships as a visible guard instead of stopping the run when another test of its Step fails without the work; the denied-terms row asserting that a slug in another case is refused was of that kind.
