# Steps that add tests to one file build in separate Lanes, and the file is joined as each Lane lands

Status: accepted. Amends 0026.

Since 0026 each Step writes its own tests, and an items file's check-author Step is folded into the Steps whose acceptance names its files. Steps share a Lane when they share a file, so every Step whose tests live in one test file became one Lane and built one after another on the top model. The denied-terms items, seven Steps over one test file, planned as one Lane; the reference planner plans the same items as six clusters in four stages, three abreast at its widest and four of them on the cheap model.

A test file that two or more Steps each name in their acceptance and list in their files, that no Step lists as other work and that is not declared a shared file, is now a joint test file. It still keeps its Steps in one MSP. It is never what puts them in one Lane, never separates them into waves, and is no coupling signal between them. Each Lane's Worker adds its own tests in its own clone, and its brief says so. When a Lane lands, mitosis joins the file three ways: the file at the commit the Lane started on, the file on the MSP's branch, and the file in the Lane's clone. Additions two Lanes made at the same place are both kept, the landed Lane's first. Where both changed the same lines, mitosis writes the file into the Lane's clone with each side marked and asks that Lane's Worker once, in its own session through the re-ask command, to join them. The joined file lands only when it holds no mark and still holds, in order, every line the branch held that the Lane had not itself changed before it was asked. A file that fails either test, a second meeting after the Worker was asked, a turn that cannot start and a Lane with no session on record each fail the Lane, and none of its work lands.

When the file is not on the base, two Lanes that each created it would have no common start to join from. The first of its Steps in input order that waits on none of the others creates it, and each other Step that waits on none of them waits for the creator's Lane. When only one Step waits, it waits for the last Step of that Lane, so the rule that makes one Lane of a producer and its only consumer puts it in the creator's Lane. A resumed run decides whether the file is on the base against the base commit the run was pinned to, so its plan does not change once the file reaches the branch.

A joint test file a Lane left alone is put back as the branch holds it before the Lane's commit, so a stray write another Lane left at that path in the checkout never lands under it. A Lane's landing commit is the record that it landed. A Lane whose commit is in the branch's history since its clone was cut is not joined again, so a run stopped between two Lanes of one batch is resumed without a test landing twice. Before mitosis marks a file it keeps the Lane's own version beside the clone, and a join that a stop cut short is asked again from that version.

Three other shapes were weighed. Running the check-author as an ordinary first Lane, as the reference planner does, puts a session that only writes tests in front of every builder and returns the tests to a session that does not build, which 0026 ended on measurement. Giving each Step a test file of its own is not mitosis's to do: the items name each test's file, and the stages after the build find a test by that name. Letting every Lane create a new file apart and asking each later Lane's Worker to join the two whole files was built and is still the path when two Lanes do create one file, but it is not planned for, because each such join is a model's edit of another Lane's tests where the three-way join is not.

Every recorded items file with two or more Steps, 70 of them, was planned on 0.21.2 and on this version, once with none of its acceptance files on the base and once with all of them there. No plan has fewer Lanes, or fewer Lanes at once, in either setting, and 58 of the 70 plans are identical. On 0.21.2 ten of the 70 ran fewer Lanes at once than the reference planner. Two of the ten now match it whether or not their test file exists: the denied-terms items plan as five Lanes in three stages, three abreast and three of them on the cheap model, and the owned-handoff-formats items as four Lanes, two abreast. Four more match it when their test file is already on the base and stay narrower when the file is new, where the creation order above holds them: the two warm-lane-clones items and desktop-mapping-basics keep their one waiting Step in the creator's Lane, and any-input-decompose runs two Lanes at once where the reference planner runs four. The desktop-reliability-ux items go from five Lanes, one of them of 32 Steps, two at once, to 26 Lanes, the largest of eight Steps, seven or eight at once against the reference planner's nine. Three are unchanged: desktop-offline-area-packs, pipeline-plugin and pull-request-plugin. Their Steps are held in one Lane by work files they share and by waiting on each other, as are the Lanes of more than one Step that desktop-reliability-ux still has, and no test file is the cause. That is another rule than the one this record changes, and it is not changed here.

Change G was built from its items file under 0018. Its test file is new and only its release-notes Step could run beside the two build Steps. That Step in a Lane of its own, started once the creator's Lane ended, was built once to measure it: 1,271 seconds against 597 and 3.57 dollars against 3.32, with the judge at 8 of 8 and the merged tests at 179 of 190 both times. Its Worker spent 603 of those seconds on two whole-suite runs the benchmark's charter asks for, and without them the build still took 668. So a Step that would be the only one waiting behind a new test file stays in the creator's Lane, and change G plans as one Lane, as before. Built that way it took 517 seconds and 3.05 dollars against 597 and 3.32, the judge again at 8 of 8 and the merged tests at 179 of 190. The plan is the same Lane with its Steps in another order, so that difference is one session's spread and no gain is claimed from it.

Three Steps that each add one test to a test file already on the base were then built by three Workers at once: two landings joined the file, it holds each test once, and the gate passed all three.

The cost is that nothing checks a joined file before the gate runs its tests. Where two Lanes each added a different block at one place both blocks stay, so a line both blocks hold, such as one import, is there twice, and two tests of one name both land; the gate's one repair per failing Lane is what removes them. A Worker cannot run another Lane's tests in its clone, so the Worker asked to join a file runs only its own. A Worker that sets out to change what another Lane's tests check can still do so by adding lines to the file: the test above catches a line changed or dropped, which is what a join in good faith gets wrong, and 0030 already leaves a run that forges its result to review. Two Steps that add tests to a new file and do not otherwise wait on each other still build one after the other. A check-author's helper file that no acceptance names still goes to every Step that takes its tests and still puts those Steps in one Lane.

The three-Worker build above is a fixture of a few lines each, and no recorded feature has yet been built with two Workers side by side on one test file: change G has one Lane, and the denied-terms items have no build on record under this version. This reopens on the first such build that lands a joined file its gate cannot run, on a build whose Worker is asked to join a file more than once in a run, or when a real build shows a Step of its own size waiting behind a new test file.
