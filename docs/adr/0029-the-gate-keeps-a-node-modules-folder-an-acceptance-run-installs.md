# The gate keeps a node_modules folder an acceptance run installs

Status: accepted. Amended by 0031.

The gate's clean checkout is reset to the commit's tree before every acceptance run, and whatever a run leaves is deleted; a referee path among the leftovers holds the MSP back with exit 9. The gate kept only the dependency folders it linked from the repository root or that the gate setup command made. A repository whose acceptance script installs node_modules itself, with none at its root, therefore had that folder deleted and installed again for every run, and each file in it that matched a referee marker was read as a referee write. Benchmark change A ended that way on 0.19.1: exit 9 with every gated MSP held back after 62 gate runs of about 37 seconds each, where the reference planner built the same change in 807 seconds. No earlier run had recorded a gate referee write.

A real folder named node_modules at the top level of the clean checkout, when the commit has none, now stays for the gate's later runs and is never walked. Under 0018 this was measured by replaying change A's gate on its built tree: 546 seconds and 31 referee writes in each MSP with the folder deleted before every run, 168 seconds and none with it kept, and the same 19 verdicts.

The rule is that narrow on purpose. Its first version also kept any folder holding `pyvenv.cfg`, the way the root's virtual environments are found. Two independent reviews showed that a test could then keep a folder under any name by writing that file into it: a planted package that shadows the test runner, or compiled files that stand in for the committed work, made a test that fails against the work read as a pass. A marker a run can write says nothing about who made the folder, and no measured repository installs a virtual environment during an acceptance run, so only the one name stays. A symbolic link under that name is deleted, so the gate never keeps a path that leaves the checkout, and a node_modules folder the commit tracks is reset like any other folder.

The cost is that what a test writes into the kept folder reaches the gate's later runs, the test runner in it included, so one test can make a later one pass. The gate cannot tell an install from a plant, because the acceptance command and the test it runs share one run. The same was already true of a root folder the gate links, which a run may replace with a real folder of its name, and of a folder the gate setup command makes. Deleting the folder before every run would close it for this case alone, at 546 seconds a gate against 168 on change A.

This reopens when a run is found whose test altered a kept folder so that a later test passed, or when a measured repository installs another kind of dependency folder during its acceptance run.
