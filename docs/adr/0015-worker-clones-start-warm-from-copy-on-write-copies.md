# Worker clones start warm from copy-on-write copies of an opt-in allowlist

Status: accepted

A Worker's clone is cut with `git clone --no-local --no-hardlinks` (ADR 0010), so it holds no gitignored file: no installed packages, no build cache, no native bundle a project's tests need. Each Lane therefore starts cold, and in some projects cannot run its tests at all. mitosis now copies into each Lane clone and the check-author's clone the paths a project lists in `.worktreeinclude` at its repository root, in gitignore syntax, the file worktrunk and Claude Code read for the same purpose, keeping only paths the repository ignores and does not track. The copies are made by copy-on-write only, clonefile(2) on macOS and `cp --reflink=always` on Linux, which took 0.06 s for a 12 GB build folder and shares disk blocks until either side writes; there is no plain-copy, hard-link or symbolic-link fallback, because a plain copy per Lane can fill a disk and a link lets a Worker's write reach the user's checkout. A path that cannot be copied leaves the Lane cold, as before. We made it opt-in rather than shipping a default list of cache folder names because pipeline runs start Workers without `--worker-sandbox` (ADR 0011), so a cache holding absolute paths back to its source could write there; only the project owner knows which caches are safe. For the same reason a Python virtual environment, a secret-looking name and a copy holding a symbolic link that leaves the clone are refused even when listed. The gate's clean checkout (ADR 0009) is never seeded, since build outputs copied from the user's checkout could change a verdict, and landing lists nothing under a seeded path, so seeded files never reach a commit.
