# Each Worker builds in its own clone

Status: accepted

Every Lane's Worker builds in a clone of its MSP branch under the run directory, made with no local hardlinks and its remote removed, so it has its own git directory and object store. The MSP worktree stays as mitosis's own checkout, where no Worker runs. When the Worker exits, mitosis reads its write-set from the clone's working tree with lstat, never running git in the clone, writes those entries into its checkout and commits them with the landing message; a write-set path behind a symbolic-link parent fails the Lane. Files changed outside the write-set are found by comparing the clone's working tree with the Lane's start tree and replayed into mitosis's checkout as uncommitted changes, so they are judged exactly as before: an undeclared write is kept and exits 6, and a locked or referee-marker write is reverted and exits 9. Only regular files and deletions are replayed, never symbolic links or paths that resolve outside the clone, and replayed files are judged by reconcile only: the gate, its mutants and every acceptance run see each such path as it stood when the Lane started, so an uncommitted helper can never make an acceptance test pass. We chose isolation over detection because eight review rounds defending a shared worktree each found a new way for a Worker to reach the refs, replace refs, grafts, settings or objects mitosis read. We chose copying bytes over fetching or bundling from the clone because both run git inside a directory the Worker controls, where its fsmonitor, hooks and filters would run with mitosis's permissions. The cost is a full object-store copy per Lane, and a Lane no longer sees a sibling's uncommitted writes.
